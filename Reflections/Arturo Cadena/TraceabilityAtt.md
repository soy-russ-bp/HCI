# TraceabilityAtt
<mark>Errors was one of the usability attributes included in the prototype.</mark> Although message errors related to using incorrectly the app were not part of the interfaces, <mark>the attribute was included because there are parts where it is possible to select or make mistakes. For example, in the flow where the user enters the critical thinking course and navigates to the next lesson</mark>. To measure this, <mark>we selected the metric error rate. This metric is considered one of the most basic and it is well known for being included in many measuring tools. The data collected for this metric was the misclick rates and this decision was taken because it is easy to obtain it with usability tests and tools like Maze, also detects in a simple way parts that should be improved.</mark>  The data were collected in a think aloud tests with potential users and all of this was registered with Maze.  

<mark>An alternative data for Errors could be the time to recover from errors.</mark> This data can be interesting because basically it might show how usable are others parts or the prototype and how difficult it is for the user to find a solution in complicated situations.
